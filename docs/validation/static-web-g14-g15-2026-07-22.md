encore une autorisation de bascule. Les tailles ont été mesurées sur les
artefacts locaux présents dans `apps/web_generator/dist` et `build/web`. Les

## Protocole reproductible de performance

Les temps de chargement et de génération ne sont pas publiés dans ce relevé :
aucun banc instrumenté stable n'a encore produit une série exploitable. Le gate
final doit utiliser le protocole suivant, sans réseau extérieur :

1. produire un build release propre, noter le commit et le hash du catalogue ;
2. servir `dist` sur `127.0.0.1`, cache navigateur désactivé pour le chargement ;
3. effectuer 5 échauffements puis 30 mesures dans Chromium ;
4. mesurer avec `performance.now()` de `navigationStart` jusqu'à
   `data-cycle-ready="true"` ;
5. mesurer séparément l'appel `generateCycle`, depuis juste avant le bridge
   jusqu'à la réception du JSON, puis le rendu jusqu'à la première carte ;
6. couvrir Standard, BBB et Two-day rotation, avec et sans plaques ;
7. publier médiane, p95, minimum et maximum, ainsi que CPU, version navigateur
   et mode cache ;
8. faire échouer le scénario si une requête sort de l'origine locale.

Le même protocole doit être exécuté sur le build Flutter de référence, avec la
même machine et le même navigateur. Pour Flutter, séparer le premier chargement
du second chargement avec cache ; ne pas comparer un Web statique chaud à un
Flutter froid.

## Gate G14/G15 à archiver

Les sorties complètes, datées et rattachées au commit final doivent couvrir :

```text
dart format --set-exit-if-changed .
dart analyze
dart test
flutter analyze
flutter test
flutter build web --release
npm ci
npm run typecheck
npm test
npm run build
npm run e2e
verify:parity
git diff --check
```

La parité n'est validée que si les 23 variantes Cycle donnent un JSON
canonique identique entre Dart natif et bridge JavaScript, et si le scénario
Forever est réellement exécuté des deux côtés. L'existence de la méthode
`generateMacrocycle` ne suffit pas.
